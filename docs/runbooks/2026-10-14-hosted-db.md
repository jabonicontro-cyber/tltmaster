## 2. Back up first (the free plan has no backups)

```bash
pg_dump "<session pooler connection string>" -Fc -f taviron-$(date +%F).dump
ls -lh taviron-*.dump    # must not be 0 bytes
```

## 3. Apply

```bash
npx supabase db push --dry-run   # should list only the pending files above
npx supabase db push             # answer Y
npx supabase migration list      # every row now shows Local and Remote
```

## 4. Verify (Supabase dashboard → SQL editor; paste and run)

```sql
select 'pto banks'            as check, to_regclass('public.pto_ledger') is not null as ok
union all select 'document rules',     to_regclass('public.vehicle_document_rules') is not null
union all select 'pto accruals',       to_regclass('public.pto_policies') is not null
union all select 'approval chains',    to_regclass('public.time_off_approval_steps') is not null
union all select 'routing',            exists (select 1 from information_schema.columns where table_schema = 'public' and table_name = 'company_settings' and column_name = 'yard_latitude')
union all select 'people backfill',    not exists (select 1 from public.company_memberships m join public.companies c on c.id = m.company_id
                                                   where not c.is_demo and not exists (select 1 from public.employees e where e.company_id = m.company_id and e.user_id = m.user_id))
union all select 'billing views',      pg_get_viewdef('public.billing_exceptions'::regclass) ilike '%lateral%'
union all select 'command center',     to_regprocedure('private.visible_exception_kinds()') is not null
union all select 'work schedules',     to_regclass('public.employee_work_schedules') is not null
union all select 'owner person',       (select pg_get_functiondef(oid) from pg_proc where proname = 'create_company_with_access_code' and pronargs = 4) ilike '%insert into public.employees%'
union all select 'driver notices',     to_regprocedure('private.alerts_from_new_assignments()') is not null and to_regprocedure('private.alerts_from_load_changes()') is not null;
```

Every row should say `true`. Then, in the app:

1. **Refresh demo data** in both demo companies (Admin → Demo). Existing demos then get sample time-off balances,
   accruals, approval chains, work schedules and route locations. Refresh never touches real companies.
2. Open People in your company: every sign-in has a person row. Open one person: the **Work schedule** card shows.
3. Open the Command Center: it loads as before (faster).
4. Assign a load to a driver who has a login: that driver sees "New load: …" under Alerts and on the bell.

If anything fails, stop and send me the error text. Each migration has a tested rollback in `supabase/rollbacks/`
(run only with a backup in hand).
